# VRCDI

> Транслирует состояние Android-устройства прямо в чатбокс VRChat.

VRCDI — небольшое Android-приложение на чистом Java: читает данные CPU / GPU / памяти / батареи и прочего через **Shizuku** (либо Root, либо вообще без привилегий), собирает отмеченные поля в многострочный текст и отправляет его в VRChat по **UDP OSC** (`/chatbox/input`). Текст появляется в чатбоксе над головой аватара.

- Пакет: `com.vrcdevicecheck.osc`
- Версия: `5.3.0 Beta4 (Build 451)`
- Подпись: начиная с **4.9.0 Release** Beta и релизные сборки подписываются одним релизным ключом. Сборки 4.4.4 Beta и старше подписаны debug-ключом, поэтому перед обновлением их нужно удалить (данные приложения будут потеряны).
- Минимум: Android 10 (API 29)
- Язык: Java 8; единственная сторонняя зависимость — Shizuku
- Сборка: Android Studio 4.2 / AGP 4.2.2 / Gradle 6.7.1 / compileSdk 30

## Возможности

**Сбор данных**

- 21 включаемое поле: бренд устройства, модель, имя / частота / температура / загрузка CPU, имя / частота / температура / загрузка GPU, занятая / общая RAM, батарея и состояние зарядки, погода / температура воздуха / влажность / давление / ветер / УФ-индекс / закат, приложение на переднем плане, частота кадров.
- Вывод **разбит на строки**, по одной категории на строку, например:
  ```
  OPPO PCAT00
  CPU: Qualcomm SM8550 2.21GHz 46.1℃ 10%
  GPU: Adreno 740 Недоступно 41.3℃ Недоступно
  RAM: 3.9/5.5GB 71%
  Батарея: 45% Заряжается
  App: VRCDI (это приложение)
  ```
- Все узлы sysfs / procfs читаются **одним shell-скриптом** (`assets/snapshot.sh`), поэтому на каждый цикл создаётся только один дочерний процесс.
- Всё, что прочитать не удалось, показывается как «Недоступно» — значения никогда не выдумываются.

**Три канала привилегий**

| Канал | Описание |
| --- | --- |
| Shizuku | Выполнение от shell (uid 2000); Shizuku должен быть установлен и запущен |
| Root | Прямой вызов `su`, без встроенных root-библиотек; распознаёт семейства KernelSU / APatch / Magisk и ведёт к выдаче прав |
| Без привилегий | Читаются только узлы, открытые обычным приложениям; температура / частота CPU чаще всего недоступны |

**Отправка OSC**

- Получатель — **это устройство** (`127.0.0.1`, если VRChat и VRCDI на одном устройстве) или **свой IP** (телефон → VRChat на ПК).
- Поддерживаются оба параметра `/chatbox/input`: «отправить сразу» и «звук уведомления».
- Одно сообщение чатбокса — до **144 символов**. Если текст длиннее, поля отбрасываются с конца по приоритету, а предпросмотр честно сообщает «опущено: xxx».

**Интервал отправки**

- Настройки (шестерёнка справа сверху) → **Интервал отправки**: 2 / 5 / 10 / 30 / 60 секунд или свой интервал **2–3600 секунд**.
- «Отправить один раз сразу при запуске» включено по умолчанию: нажатие «Запустить» сразу собирает и отправляет отчёт, дальше цикл идёт по интервалу.
- Если сохранить настройки во время работы, **перепланирование происходит сразу**, не дожидаясь конца текущего цикла; строка «каждые X с» в уведомлении тоже обновляется.
- Короткий интервал обновляет быстрее, но сильнее расходует батарею. Сейчас VRChat допускает примерно **5 сообщений за 5 секунд** (раньше лимит был строже) — если чатбокс перестал обновляться, увеличьте интервал.

**Автоскрытие недоступных полей**

- Внизу карточки полей есть переключатель «Скрывать недоступные поля автоматически», **включён по умолчанию**.
- Поля со значением «Недоступно» не попадают в текст и не расходуют лимит 144 символа; интерфейс сообщает «скрыто N недоступных полей».
- Если выключить, поведение прежнее: нечитаемые значения показываются как «Недоступно».
- Скрытые поля и поля, отброшенные из-за превышения 144 символов, считаются отдельно, поэтому предупреждение о длине никогда не врёт.

**Погода**

- Настройки (шестерёнка) → **Город для погоды**: внутри Китая выбор идёт по схеме провинция → город, встроено 34 провинции и 346 городов.
- **Поддерживаются города за пределами Китая**:
  - Первый пункт списка «Поиск города» ищет любой город мира по названию (по-китайски или по-английски, например `Tokyo`);
  - Последний пункт «Выбор зарубежных» позволяет листать **страна → город**: встроено 240 стран и более 2100 городов, работает без сети;
  - Оба пути сохраняют широту и долготу напрямую, и все три источника погоды запрашиваются по координатам, а не по названию.
- Результаты поиска сортируются по населению; для запросов иероглифами дополнительно пробуется традиционное написание (东京 → 東京), чтобы не находились только мелкие одноимённые города внутри Китая.
- Новые поля: **погода / температура воздуха / влажность / давление / ветер / УФ-индекс / закат**; по умолчанию выключены, а если включить их без выбранного города, приложение предложит выбрать город.
- Погода занимает две строки: в первой погода / температура / влажность, во второй давление / ветер / УФ / закат. При переполнении сначала отбрасывается вторая строка, чтобы базовая информация осталась.
- Ветер показывается в 8 румбах (например, «ЮЗ ветер 3.2m/s»), давление в hPa, УФ как индекс 0–11+, закат по местному времени HH:mm.
- Основной источник — **Open-Meteo** (бесплатно, без ключа); если `api.open-meteo.com` недоступен, приложение переключается на **wttr.in** (тоже бесплатно и без ключа), поэтому погода работает и в ограниченных сетях.
- **Кэш на 30 минут**: после успешного запроса отметка времени пишется в SharedPreferences, и тот же город не запрашивается повторно в течение 30 минут — переживает и завершение процесса, и перезагрузку. После ошибки повторная попытка не раньше чем через 10 минут, чтобы не раздувать число запросов.
- Ручная кнопка «Получить сейчас» подчиняется тем же 30 минутам: повторное нажатие для того же города покажет, сколько минут осталось; **смена города очищает кэш**, поэтому сразу после смены можно получать данные.
- Разрешение на геолокацию не нужно — запрашивается только выбранный город, а данные погоды остаются на устройстве.

**Таблица устройств (модель → название продукта)**

- Импорт JSON-таблицы по бренду: файл копируется в приватный каталог приложения `files/device_tables/<бренд>.json`, пересборка не требуется.
- «Тип отображаемой модели» переключает **реальную модель** (например, `HUAWEI HED-AL00`) и **маркетинговое название** (например, `HUAWEI Pura 80`).

**Темы**

- **Встроенные палитры**: Настройки → Тема, выбор в один тап — Crimson / Mist blue / Sakura / Pine / Amber / Violet. Меняются только фон, карточки, основной и второстепенный текст, применяется сразу.
- Все встроенные палитры светлые. Для тёмного вида нужны свои изображения кнопок и полей — это и есть путь импорта ниже.
- Импорт пакета `.zip` / `.tar.gz`; он копируется в `files/themes/<имя темы>/`.
- В пакет можно положить фоновое изображение, изображения кнопок (включая нажатое состояние) и JSON с цветами — для сложного оформления.
- После переключения приложение перезапускается; долгое нажатие на импортированную тему в настройках удаляет её (встроенные палитры удалить нельзя).

**Таблица приложений (пакет → имя)**

- Популярные приложения уже встроены (QQ, WeChat, VRChat и другие), свои можно добавить импортом JSON.
- «Приложение на переднем плане» сначала ищется в таблице приложений, затем берётся системное имя, и только потом показывается имя пакета.

**Обновление внутри приложения**

- Настройки → Обновление ПО: источник **Gitee** или **GitHub**.
- Приложение читает API релизов, сравнивает последний тег с текущей версией, скачивает вложение и передаёт его системному установщику.
- Скачанные APK лежат в `cache/update/`; если вложение называется `.apk.zip`, оно автоматически трактуется как `.apk`.

**Язык интерфейса**

- Настройки → **Язык / 语言**: 简体中文 (по умолчанию), English, 日本語, Русский, 한국어. После переключения приложение перезапускается.
- **Текст, отправляемый в чатбокс VRChat, тоже следует языку интерфейса** — китайский, английский, японский, русский или корейский; лимит 144 символа не меняется.
- «Только ASCII» важнее языка: при включении принудительно используется английская ASCII-запись (`℃` → `C`), чтобы VRChat не показывал вопросительные знаки.
- Китайский — язык по умолчанию, лежит в `values/`; остальные — в `values-en` / `values-ja` / `values-ru` / `values-ko`, ключи во всех пяти наборах совпадают один к одному.
- В японском, русском и корейском интерфейсе названия мест и текст погоды берутся из английских данных (встроенная база городов содержит только китайские и английские названия).

**Гид при первом запуске**

- При чистой установке приложение сначала предлагает выбрать язык (каждый язык подписан на нём самом), затем сразу переключается.
- Далее идёт иллюстрированное руководство «включите OSC в VRChat»: 5 реальных скриншотов с одной подписью каждый, отдельный набор для каждого языка (китайский / английский / японский / русский / корейский).
- Пользователям, обновляющимся со старой версии, гид не показывается (наличие настроек считается признаком пройденного гида).
- Перечитать можно в любой момент: Настройки → **Настройка OSC**.

**Прочее**

- Отправка идёт в foreground-сервисе, остановить можно прямо из уведомления. Журнал хранит последние 50 записей только в памяти.
- Определение «приложения на переднем плане» (нужно системное разрешение «Доступ к использованию»).

## Установка и использование

1. Установите APK (со страницы релизов или собрав самостоятельно).
2. Откройте приложение: при первом запуске оно попросит выбрать язык и покажет руководство «как включить OSC в VRChat» (повторно — Настройки → **Настройка OSC**).
3. Нажмите **шестерёнку** справа сверху, чтобы открыть настройки:
   - **Интервал отправки**: от 2 до 3600 секунд и опция отправки сразу при запуске.
   - **Город для погоды**: выбор места по схеме провинция → город.
   - **Способ привилегий**: Shizuku / Root / без авторизации.
   - **Таблицы устройств**: импорт таблиц по брендам (необязательно).
   - **Таблицы приложений**: импорт соответствий пакет → имя (необязательно).
   - **Тема**: импорт и переключение тем (необязательно).
   - **Обновление ПО**: выбор источника, проверка и установка.
   - **О VRCDI**: версия, авторы и данные устройства (включая CPU / GPU).
4. В блоке **Подключение** выберите получателя:
   - VRChat и VRCDI на одном устройстве → **Это устройство**;
   - Телефон отправляет на VRChat на ПК → **Свой...** и введите локальный IP компьютера.
5. В блоке **Отправляемые поля** отметьте нужное (в строке модели можно переключить реальную модель и название продукта).
6. Нажмите **Запустить отправку**. Появится уведомление foreground-сервиса, из него же можно остановить.

### Со стороны VRChat (обязательно при отправке на ПК)

1. VRChat Action Menu → Options → OSC → **Enabled**.
2. По умолчанию VRChat слушает только `127.0.0.1`; для отправки с другого устройства нужно добавить параметр запуска (Steam → Свойства → Параметры запуска):

   ```
   --osc=9000:<LAN IP ПК>:9001
   ```

   Главный экран приложения собирает эту строку сам — достаточно скопировать.
3. Разрешите UDP 9000 в брандмауэре ПК и убедитесь, что порт не занят софтом для трекинга лица или тела.

> Примечание: OSC односторонний, у UDP нет подтверждения доставки. «Отправлено» в журнале означает лишь то, что датаграмма передана сетевому стеку ОС. Дошла ли она, лучше проверять в панели OSC Debug в Action Menu VRChat.

## Формат таблицы устройств

`Таблицы устройств → Создать таблицу по бренду`: введите название бренда, выберите JSON-файл, и он будет скопирован без изменений в `files/device_tables/<бренд>.json`.

```json
{
  "devices": [
    { "model": "HED-AL00", "match": "exact",  "series": "Pura 80",     "verified": true },
    { "model": "LMR-AL",  "match": "prefix", "series": "Pura 80 Pro", "verified": false }
  ]
}
```

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `model` | да | Код модели, соответствует `ro.product.model` / `Build.MODEL`, сравнение без учёта регистра |
| `series` | да | Название продукта, показывается при выборе «Название продукта» |
| `match` | нет | `exact` (по умолчанию, полное совпадение) или `prefix` (модель начинается с этого — удобно для вариантов) |
| `verified` | нет | Только пометка, в интерфейсе не используется |

- Верхний уровень может быть и просто массивом; файл читается как UTF-8 (BOM допускается).
- Порядок загрузки: `files/device_tables/*.json` → старый `files/device_models.json` → встроенный `assets/device_models.json`; побеждает первое совпадение.
- Название продукта сначала берётся из системных свойств (`ro.product.marketname` и подобных), и только потом из таблицы устройств.

## Формат пакета темы

Поддерживаются `.zip` и `.tar.gz` / `.tgz`; после распаковки должен найтись `theme.json`:

```
mytheme.zip
├── theme.json                 # обязательно
└── images/
    ├── background.png         # необязательно, фон окна
    ├── button.png             # необязательно, обычная кнопка
    └── button_pressed.png     # необязательно, нажатая кнопка
```

```json
{
  "name": "Ночной полёт",
  "colors": {
    "background": "#0F1216",
    "card": "#1A1F24",
    "text": "#E8EAED",
    "textSecondary": "#A0A8B0"
  },
  "images": {
    "background": "images/background.png",
    "button": "images/button.png",
    "buttonPressed": "images/button_pressed.png"
  }
}
```

- Всё, кроме `name`, необязательно; цвета в формате `#RRGGBB` / `#AARRGGBB`; пути к изображениям относительны каталога темы.
- Имя темы становится именем каталога; повторный импорт с тем же именем перезаписывает его.
- После переключения приложение перезапускается; долгое нажатие на тему в настройках удаляет её.

## Сборка из исходников

```bash
./gradlew assembleDebug      # создаёт app/build/outputs/apk/debug/app-debug.apk
./gradlew test               # запускает JVM-тесты (кодирование OSC, разбор, сборка текста и т.д.)
```

- Нужны JDK 11 и Android SDK 30 (build-tools 30.0.3).
- Проект намеренно остаётся «чистым Java без виджетов AndroidX»: все экраны построены на `android.app.Activity` и нативных View, поэтому собирается и в старых окружениях (например, Android Studio 4.2).
- Единственная сторонняя зависимость — `dev.rikka.shizuku:api` / `provider` (12.1.0); она транзитивно требует `androidx.annotation`, поэтому в `gradle.properties` нужен `android.useAndroidX=true` (AppCompat при этом не подключается, все экраны остаются нативными Activity).

### Иконка приложения

В репозитории нет исходника иконки. Когда он появится, выполните один раз:

```powershell
powershell -ExecutionPolicy Bypass -File tools\make_icons.ps1 -Source "<путь к изображению>"
```

Скрипт создаст `ic_launcher.png` для всех плотностей и передний план адаптивной иконки, а также переключит XML иконок в `mipmap-anydpi-v26` на новый передний план.

## Известные ограничения

- **Данные GPU наименее надёжны**: в Android нет публичного API для частоты / температуры / загрузки GPU, всё зависит от вендорских узлов sysfs. На Unisoc и части MediaTek их не прочитать даже с root, и интерфейс покажет «Недоступно». Имя GPU берётся из GL `GL_RENDERER` (без разрешений), и только при неудаче — из sysfs.
- **Ограничение частоты чатбокса**: по измерениям сообщества — около «5 сообщений за 5 секунд»; при превышении включается пауза. Интервал по умолчанию 10 секунд выбран с запасом.
- **Отображение не-ASCII**: транспорт всегда UTF-8, но разные версии VRChat по-разному поддерживают не-ASCII; включите «Только ASCII», чтобы гарантированно что-то увидеть.
- **Quest standalone**: устанавливается и работает, но на Quest нет root, а Shizuku официально не поддерживается, поэтому температура / частота чаще всего недоступны; поддержка OSC-ввода в VRChat на Quest зависит от версии системы — проверяйте сами.
- **Определение переднего приложения** требует системного разрешения «Доступ к использованию»; без него поле показывает «Недоступно».
